# Provenance

Every entity in this repository -- the company, its distributors, products, sales
reps, and all transaction data -- is fictional, generated by
`tools/generate_data.py` from a fixed seed (default `20260727`). **Tuppi Trading
Co.**, its eight distributors (Cedar Route Distribution, Harborlight Distribution,
and so on), its fifty products across four categories, and its twelve sales reps
exist only as output of that generator. None of it refers to, or was derived from,
any real company, market, or dataset.

## The generator is the shipped artifact, not the data

`data/` is gitignored and is never committed to this repository, at any commit, in
any branch. If you can see a `data/` directory here, you generated it yourself:

```
python tools/generate_data.py
```

The same default seed always produces byte-identical files; a different `--seed`
produces a different (but still internally consistent) fictional dataset. This
means the generator -- readable, auditable Python, not a data dump -- is the actual
artifact this repository ships. Auditing it is legitimate source work, not a
workaround.

## Planted defects, documented

The generator plants three deliberate, deterministic data-quality defects, used by
this repository's tasks and its governance tooling:

- **P1 -- double-loaded batch.** One mid-year day's import is duplicated verbatim
  under a second batch id. This is what makes `tools/reconcile.py` fail out of the
  box, and what task T2 (`tasks/T2_fix_reconciliation.md`) asks an agent to fix.
- **P2 -- orphan products.** A handful of transactions reference a product id that
  was never added to `products.csv` -- background texture for master-data-drift
  tasks, not used by v1's shipped tasks.
- **P3 -- reporting gap.** One distributor goes silent for about three weeks --
  background texture for a future freshness-signal task.

These are not bugs in this repository; they are the point of it. See
`tools/generate_data.py`'s own docstring for the exact mechanics of each.

## Dependency

This repository depends on the `kibsu` package from PyPI (`kibsu>=0.9.0` in this
repo's own tooling notes; CI in `.github/workflows/lab-ci.yml` pins the exact
version, `kibsu==0.9.0`, for reproducibility) to read and report on its own
governance -- `AGENTS.md`, `skills/`, `docs/`. kibsu-lab is that package's first
real deployment outside its own source tree.
